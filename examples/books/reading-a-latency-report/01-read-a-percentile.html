1 - Read a percentile

A latency report starts with a set of measurements. Here, each measurement is the time from the arrival of a request at the museum website to the moment the website finishes sending a response. Think of every request as one observation.

Sort the measurements

Suppose the website records twenty requests in one short observation window. The table lists their response times from fastest to slowest. Some values occur twice because different requests took the same amount of time.

The median lies halfway between the two middle measurements, 94 and 95, so it is 94.5 milliseconds. This describes the center of the sample. If you want to know what happened to visitors who waited longer, look higher up the ordered list.

Find the 95th percentile

For the 95th percentile, multiply the number of observations by 0.95 and round up to the next integer if needed. Then read the measurement at that rank. This rule is called the nearest-rank method. Other methods can give slightly different values for a small sample.

Here, 0.95 × 20 = 19. The 19th measurement is 240 milliseconds, so the 95th percentile, or p95, is 240 milliseconds. Nineteen of the twenty requests took 240 milliseconds or less. The slowest request took 790 milliseconds, which is more than three times as long.

Check the slowest requests

The tail of this distribution contains the relatively rare requests that take a long time. If the slowest request rises to 1,200 milliseconds while the other nineteen stay the same, the p95 is still 240 milliseconds. The report can show the p95 alongside the number of requests above a given threshold, such as one second, to make that change visible.

Keep the sample size in view. In a sample of twenty, one request accounts for five percent of the observations. A single delay can therefore have a large effect on a high percentile. A larger sample gives you more evidence about how often slow responses occur.
